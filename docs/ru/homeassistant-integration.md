# Руководство по интеграции ESP32-устройств Сяочжи (открытый сервер) с HomeAssistant

## Введение

Этот документ поможет вам интегрировать устройство ESP32 с HomeAssistant.

## Предварительные условия

- Установлен и настроен `HomeAssistant`
- В этот раз я выбрал модель: бесплатный ChatGLM, он поддерживает вызовы функций (functioncall)

## Действия перед началом (обязательно)

### 1. Получение сетевого адреса HA

Откройте в браузере сетевой адрес вашего Home Assistant, например, у меня адрес HA — 192.168.4.7, порт стандартный 8123, тогда открываем

```
http://192.168.4.7:8123
```

> Ручной способ узнать IP-адрес HA **(только если xiaozhi-esp32-server и HA развёрнуты в одной сети [например, в одной Wi-Fi-сети])**:
>
> 1. Зайдите в Home Assistant (веб-интерфейс).
>
> 2. Нажмите в левом нижнем углу **Настройки (Settings)** → **Система (System)** → **Сеть (Network)**.
>
> 3. Прокрутите до самого низа, до раздела `Home Assistant URL (адрес Home Assistant)`, в пункте `Локальная сеть (local network)` нажмите кнопку `глаз`, чтобы увидеть текущий IP-адрес (например, `192.168.1.10`) и сетевой интерфейс. Нажав `Скопировать ссылку (copy link)`, можно скопировать адрес напрямую.
>
>    ![image-20250504051716417](../images/image-ha-integration-01.png)

Либо, если у вас уже настроен OAuth-адрес Home Assistant с прямым доступом, вы можете открыть его в браузере напрямую

```
http://homeassistant.local:8123
```

### 2. Вход в `Home Assistant` и получение ключа разработчика

Войдите в `HomeAssistant`, нажмите `аватар в левом нижнем углу -> Профиль`, перейдите на вкладку `Безопасность`, прокрутите до самого низа и сгенерируйте api_key в разделе `Долгоживущие токены доступа`, затем скопируйте и сохраните его — во всех дальнейших способах нужен этот api key, и он отображается только один раз (маленький совет: можно сохранить сгенерированное изображение QR-кода и позже извлечь из него api key ещё раз, отсканировав код).

## Способ 1: функция вызова HA, созданная сообществом Сяочжи

### Описание функции

- Если позже потребуется добавить новые устройства, при этом способе нужно вручную перезапустить `xiaozhi-esp32-server (сервер)`, чтобы обновить информацию об устройствах **(важно**).

- Убедитесь, что в HomeAssistant уже интегрирован `Xiaomi Home` и устройства Mi Home импортированы в `HomeAssistant`.

- Убедитесь, что `панель управления xiaozhi-esp32-server` работает нормально.

- Моя `панель управления xiaozhi-esp32-server` и `HomeAssistant` развёрнуты на одной машине, но на разных портах, версия `0.3.10`

  ```
  http://192.168.4.7:8002
  ```


### Шаги настройки

#### 1. Войдите в `HomeAssistant` и составьте список устройств для управления

Войдите в `HomeAssistant`, нажмите `Настройки` в левом нижнем углу, затем перейдите в `Устройства и службы` и нажмите `Объекты` (Entities) вверху.

Затем найдите в объектах нужные вам выключатели. Когда результаты появятся в списке, нажмите на один из них — откроется экран выключателя.

На экране выключателя попробуйте нажать на него и проверьте, включается/выключается ли он. Если устройство реагирует, значит, оно нормально подключено к сети.

Затем на панели выключателя найдите кнопку настроек, нажмите её — можно будет посмотреть `идентификатор объекта` (Entity ID) этого выключателя.

Откройте блокнот и составьте одну запись в таком формате:

позиция + английская запятая + название устройства + английская запятая + `идентификатор объекта` + английская точка с запятой

Например, я на работе, у меня есть игрушечная лампа, её идентификатор — switch.cuco_cn_460494544_cp1_on_p_2_1, тогда запись будет такой:

```
公司,玩具灯,switch.cuco_cn_460494544_cp1_on_p_2_1;
```

В итоге мне, возможно, нужно управлять двумя лампами, итоговый результат:

```
公司,玩具灯,switch.cuco_cn_460494544_cp1_on_p_2_1;
公司,台灯,switch.iot_cn_831898993_socn1_on_p_2_1;
```

Эту строку мы называем «строкой списка устройств» — сохраните её, она скоро понадобится.

#### 2. Вход в `панель управления`

![image-20250504051716417](../images/image-ha-integration-06.png)

Войдите в `панель управления` под учётной записью администратора. В разделе `Управление агентами` найдите своего агента и нажмите `Настроить роль`.

Установите распознавание намерений в `внешнее распознавание намерений большой моделью` или `автономные вызовы функций большой моделью`. Справа появится кнопка `Редактировать функции`. Нажмите её — откроется окно `Управление функциями`.

В окне `Управление функциями` нужно отметить галочками `Запрос состояния устройств HomeAssistant` и `Изменение состояния устройств HomeAssistant`.

После этого в разделе `Выбранные функции` нажмите `Запрос состояния устройств HomeAssistant` и в `Настройке параметров` укажите адрес вашего `HomeAssistant`, ключ и строку списка устройств.

После редактирования нажмите `Сохранить настройки` — окно `Управление функциями` закроется, после чего снова нажмите сохранение настроек агента.

После успешного сохранения можно будить устройство и управлять им.

#### 3. Пробуждение устройства и управление

Попробуйте сказать esp32: «Включи лампу XXX».

## Способ 2: использование голосового помощника Home Assistant как инструмента LLM в Сяочжи

### Описание функции

- У этого способа есть довольно серьёзный недостаток — **при нём невозможно использовать возможности плагинов function_call открытой экосистемы Сяочжи**, поскольку использование Home Assistant как инструмента LLM передаёт распознавание намерений самому Home Assistant. Однако **этот способ позволяет получить нативный опыт работы с функциями Home Assistant, при этом чат-возможности Сяочжи остаются прежними**. Если это критично, можно использовать [Способ 3](#способ-3-использование-mcp-сервера-home-assistant-рекомендуется), который также поддерживает Home Assistant и позволяет в максимальной степени воспользоваться его возможностями.

### Шаги настройки:

#### 1. Настройте голосового помощника Home Assistant с большой языковой моделью.

**Заранее настройте голосового помощника Home Assistant или инструмент большой модели.**

#### 2. Получите Agent ID голосового помощника Home Assistant.

1. Откройте страницу Home Assistant. В левом меню нажмите `Инструменты разработчика`.
2. В открывшемся `Инструменте разработчика` перейдите на вкладку `Действия` (операция 1 на рисунке), в поле `Действие` на странице найдите или введите `conversation.process (диалог: обработать)` и выберите `Диалог (conversation): обработать` (операция 2 на рисунке).

![image-20250504043539343](../images/image-ha-integration-02.png)

3. На странице отметьте опцию `Агент (agent)` и в ставшем активным поле `Диалоговый агент (conversation agent)` выберите имя голосового помощника, настроенного на шаге 1. Как показано на рисунке, у меня настроен `ZhipuAi` — выбираю его.

![image-20250504043854760](../images/image-ha-integration-03.png)

4. После выбора нажмите `Перейти в YAML-режим` в левом нижнем углу формы.

![image-20250504043951126](../images/image-ha-integration-04.png)

5. Скопируйте значение agent-id, например, на рисунке у меня это `01JP2DYMBDF7F4ZA2DMCF2AGX2` (только для примера).

![image-20250504044046466](../images/image-ha-integration-05.png)

6. Перейдите в файл `config.yaml` открытого сервера Сяочжи `xiaozhi-esp32-server`, в настройках LLM найдите Home Assistant и укажите сетевой адрес вашего Home Assistant, Api key и только что полученный agent_id.
7. В файле `config.yaml` измените значение `LLM` в свойстве `selected_module` на `HomeAssistant`, а `Intent` — на `nointent`.
8. Перезапустите открытый сервер Сяочжи `xiaozhi-esp32-server` — всё готово к работе.

## Способ 3: использование MCP-сервера Home Assistant (рекомендуется)

### Описание функции

- Заранее интегрируйте и установите в Home Assistant интеграцию HA — [Model Context Protocol Server](https://www.home-assistant.io/integrations/mcp_server/).

- Этот способ, как и способ 2, является официальным решением HA. В отличие от способа 2, здесь можно нормально использовать совместно разрабатываемые плагины открытого сервера Сяочжи `xiaozhi-esp32-server`, а также использовать любую LLM с поддержкой function_call.

### Шаги настройки

#### 1. Установите интеграцию MCP-сервера Home Assistant.

Официальный сайт интеграции — [Model Context Protocol Server](https://www.home-assistant.io/integrations/mcp_server/).

Или выполните следующие действия вручную.

> - Перейдите на страницу **[Настройки > Устройства и службы (Settings > Devices & Services.)](https://my.home-assistant.io/redirect/integrations)** в Home Assistant.
>
> - В правом нижнем углу нажмите кнопку **[Добавить интеграцию (Add Integration)](https://my.home-assistant.io/redirect/config_flow_start?domain=mcp_server)**.
>
> - Из списка выберите **Модель протокола контекста (Model Context Protocol Server)**.
>
> - Следуйте инструкциям на экране, чтобы завершить настройку.

#### 2. Настройка MCP в открытом сервере Сяочжи


Перейдите в каталог `data` и найдите файл `.mcp_server_settings.json`.

Если в вашем каталоге `data` нет файла `.mcp_server_settings.json`:
- скопируйте файл `mcp_server_settings.json` из корневого каталога папки `xiaozhi-server` в каталог `data` и переименуйте его в `.mcp_server_settings.json`
- или [скачайте этот файл](https://github.com/xinnan-tech/xiaozhi-esp32-server/blob/main/main/xiaozhi-server/mcp_server_settings.json) в каталог `data` и переименуйте его в `.mcp_server_settings.json`


Измените этот фрагмент в `"mcpServers"`:

```json
"Home Assistant": {
      "command": "mcp-proxy",
      "args": [
        "http://YOUR_HA_HOST/mcp_server/sse"
      ],
      "env": {
        "API_ACCESS_TOKEN": "YOUR_API_ACCESS_TOKEN"
      }
},
```

Примечание:

1. **Замена значений:**
   - Замените `YOUR_HA_HOST` в `args` на адрес вашего сервиса HA; если ваш адрес уже содержит префикс https/http (например, `http://192.168.1.101:8123`), достаточно указать только `192.168.1.101:8123`.
   - Замените `YOUR_API_ACCESS_TOKEN` у `API_ACCESS_TOKEN` в `env` на ранее полученный ключ разработчика api key.
2. **Если добавляемая вами конфигурация находится внутри скобок `"mcpServers"` и после неё нет других настроек `mcpServers`, нужно убрать последнюю запятую `,`**, иначе возможна ошибка парсинга.

**Итоговый результат должен выглядеть примерно так (для примера)**:

```json
 "mcpServers": {
    "Home Assistant": {
      "command": "mcp-proxy",
      "args": [
        "http://192.168.1.101:8123/mcp_server/sse"
      ],
      "env": {
        "API_ACCESS_TOKEN": "abcd.efghi.jkl"
      }
    }
  }
```

#### 3. Настройка системных параметров открытого сервера Сяочжи

1. **Выберите любую LLM с поддержкой function_call в качестве чат-помощника Сяочжи (но не выбирайте Home Assistant как инструмент LLM)**. В этот раз я выбрал модель: бесплатный ChatGLM, он поддерживает вызовы функций (functioncall), но иногда работает нестабильно; если нужна стабильность, рекомендую установить LLM: DoubaoLLM, конкретная model_name: doubao-1-5-pro-32k-250115.

2. Перейдите в файл `config.yaml` открытого сервера Сяочжи `xiaozhi-esp32-server`, настройте вашу LLM и измените `Intent` в конфигурации `selected_module` на `function_call`.

3. Перезапустите открытый сервер Сяочжи `xiaozhi-esp32-server` — всё готово к работе.
