# Руководство по интеграции ragflow

Это руководство состоит из двух частей:

- 1. Как развернуть ragflow
- 2. Как настроить интерфейс ragflow в панели управления

Если вы хорошо знакомы с ragflow и уже развернули его, можно сразу перейти ко второй части. Но если вы хотите, чтобы вам помогли развернуть ragflow так, чтобы он мог совместно с `xiaozhi-esp32-server` использовать базовые сервисы `mysql` и `redis`, снижая затраты ресурсов, начните с первой части.

# Часть 1. Как развернуть ragflow
## Шаг 1. Проверьте доступность mysql и redis

ragflow зависит от базы данных `mysql`. Если вы ранее уже развернули `панель управления`, значит, `mysql` у вас уже установлен. Можно использовать её совместно.

Попробуйте выполнить на хост-машине команду `telnet`, чтобы проверить, доступен ли порт `3306` `mysql`.
``` shell
telnet 127.0.0.1 3306

telnet 127.0.0.1 6379
```
Если порты `3306` и `6379` доступны, пропустите следующий текст и переходите сразу ко второму шагу.

Если доступа нет, вспомните, как вы устанавливали `mysql`.

Если mysql был установлен вами вручную из установочного пакета, значит, для `mysql` настроена сетевая изоляция. Возможно, сначала нужно решить проблему доступа к порту `3306` `mysql`.

Если `mysql` был установлен через `docker-compose_all.yml` этого проекта. Найдите файл `docker-compose_all.yml`, с помощью которого вы тогда создавали базу данных, и измените следующее:

До изменения
``` yaml
  xiaozhi-esp32-server-db:
    ...
    networks:
      - default
    expose:
      - "3306:3306"
  xiaozhi-esp32-server-redis:
    ...
    expose:
      - 6379
```

После изменения
``` yaml
  xiaozhi-esp32-server-db:
    ...
    networks:
      - default
    ports:
      - "3306:3306"
  xiaozhi-esp32-server-redis:
    ...
    ports:
      - "6379:6379"
```

Обратите внимание: `expose` у `xiaozhi-esp32-server-db` и `xiaozhi-esp32-server-redis` меняется на `ports`. После изменения нужно перезапустить. Команды перезапуска mysql:

``` shell
# 进入你docker-compose_all.yml所在的文件夹，例如我的是xiaozhi-server
cd xiaozhi-server
docker compose -f docker-compose_all.yml down
docker compose -f docker-compose.yml up -d
```

После запуска снова выполните на хост-машине команду `telnet`, чтобы проверить, доступен ли порт `3306` `mysql`.
``` shell
telnet 127.0.0.1 3306

telnet 127.0.0.1 6379
```
Как правило, после этого порты станут доступны.

## Шаг 2. Создайте базу данных и пользователя
Если хост-машина нормально подключается к базе данных mysql, создайте в mysql базу данных с именем `rag_flow` и пользователя `rag_flow` с паролем `infini_rag_flow`.

``` sql
-- 创建数据库
CREATE DATABASE IF NOT EXISTS rag_flow CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

-- 创建用户并授权
CREATE USER IF NOT EXISTS 'rag_flow'@'%' IDENTIFIED BY 'infini_rag_flow';
GRANT ALL PRIVILEGES ON rag_flow.* TO 'rag_flow'@'%';

-- 刷新权限
FLUSH PRIVILEGES;
```

## Шаг 3. Скачайте проект ragflow

Найдите на компьютере папку для размещения проекта ragflow. Например, у меня это папка `/home/system/xiaozhi`.

С помощью команды `git` можно скачать проект ragflow в эту папку; в этом руководстве для установки и развёртывания используется версия `v0.22.0`.
```
git clone https://ghfast.top/https://github.com/infiniflow/ragflow.git
cd ragflow
git checkout v0.22.0
```
После скачивания перейдите в папку `docker`.
``` shell
cd docker
```
Отредактируйте файл `docker-compose.yml` в папке `ragflow/docker`: уберите настройку `depends_on` у сервисов `ragflow-cpu` и `ragflow-gpu`, чтобы снять зависимость сервиса `ragflow-cpu` от `mysql`.

До изменения:
``` yaml
  ragflow-cpu:
    depends_on:
      mysql:
        condition: service_healthy
    profiles:
      - cpu
  ...
  ragflow-gpu:
    depends_on:
      mysql:
        condition: service_healthy
    profiles:
      - gpu
```
После изменения:
``` yaml
  ragflow-cpu:
    profiles:
      - cpu
  ...
  ragflow-gpu:
    profiles:
      - gpu
```

Затем отредактируйте файл `docker-compose-base.yml` в папке `ragflow/docker`, удалив настройки `mysql` и `redis`.

Например, до удаления:
``` yaml
services:
  minio:
    image: quay.io/minio/minio:RELEASE.2025-06-13T11-33-47Z
    ...
  mysql:
    image: mysql:8.0
    ...
  redis:
    image: redis:6.2-alpine
    ...
```

После удаления
``` yaml
services:
  minio:
    image: quay.io/minio/minio:RELEASE.2025-06-13T11-33-47Z
    ...
```
## Шаг 4. Измените настройки переменных окружения

Отредактируйте файл `.env` в папке `ragflow/docker`, найдите указанные ниже настройки и изменяйте их по одной: ищите, изменяете! Ищите, изменяете!

При изменении файла `.env` 60% людей пропускают настройку `MYSQL_USER`, из-за чего ragflow не запускается, поэтому подчеркнём это трижды:

Подчёркиваем первый раз: если в вашем файле `.env` нет настройки `MYSQL_USER`, добавьте её в конфигурационный файл!

Подчёркиваем второй раз: если в вашем файле `.env` нет настройки `MYSQL_USER`, добавьте её в конфигурационный файл!

Подчёркиваем третий раз: если в вашем файле `.env` нет настройки `MYSQL_USER`, добавьте её в конфигурационный файл!

``` env
# 端口设置
SVR_WEB_HTTP_PORT=8008           # HTTP端口
SVR_WEB_HTTPS_PORT=8009          # HTTPS端口
# MySQL配置 - 修改为您本地MySQL的信息
MYSQL_HOST=host.docker.internal  # 使用host.docker.internal让容器访问主机服务
MYSQL_PORT=3306                  # 本地MySQL端口
MYSQL_USER=rag_flow              # 上面创建的用户名，如果没有这项就增加这一项
MYSQL_PASSWORD=infini_rag_flow   # 上面设置的密码
MYSQL_DBNAME=rag_flow            # 数据库名称

# Redis配置 - 修改为您本地Redis的信息
REDIS_HOST=host.docker.internal  # 使用host.docker.internal让容器访问主机服务
REDIS_PORT=6379                  # 本地Redis端口
REDIS_PASSWORD=                  # 如果你的Redis没有设置密码，就按这样子填写，否则填写密码
```

Обратите внимание: если у вашего Redis нет пароля, дополнительно измените файл `service_conf.yaml.template` в папке `ragflow/docker`, заменив `infini_rag_flow` на пустую строку.

До изменения
``` shell
redis:
  db: 1
  password: '${REDIS_PASSWORD:-infini_rag_flow}'
  host: '${REDIS_HOST:-redis}:6379'
```
После изменения
``` shell
redis:
  db: 1
  password: '${REDIS_PASSWORD:-}'
  host: '${REDIS_HOST:-redis}:6379'
```

## Шаг 5. Запустите сервис ragflow
Выполните команду:
``` shell
docker-compose -f docker-compose.yml up -d
```
После успешного выполнения можно посмотреть логи сервиса `docker-ragflow-cpu-1` командой `docker logs -n 20 -f docker-ragflow-cpu-1`.

Если в логах нет ошибок, значит, сервис ragflow запустился успешно.

# Шаг 5. Регистрация аккаунта
Откройте в браузере `http://127.0.0.1:8008`, нажмите `Sign Up` и зарегистрируйте аккаунт.

После успешной регистрации можно нажать `Sign In` и войти в сервис ragflow. Если вы хотите отключить регистрацию в сервисе ragflow, чтобы другие люди не могли регистрировать аккаунты, в файле `.env` в папке `ragflow/docker` установите значение `0` у параметра `REGISTER_ENABLED`.

``` dotenv
REGISTER_ENABLED=0
```
После изменения перезапустите сервис ragflow.
``` shell
docker-compose -f docker-compose.yml down
docker-compose -f docker-compose.yml up -d
```

# Шаг 6. Настройка моделей сервиса ragflow
Откройте в браузере `http://127.0.0.1:8008`, нажмите `Sign In` и войдите в сервис ragflow. Нажмите `аватар` в правом верхнем углу страницы и перейдите на страницу настроек.
Сначала в левой панели навигации нажмите `Поставщики моделей` и перейдите на страницу настройки моделей. В поле поиска `Доступные модели` справа выберите `LLM`, в списке выберите поставщика модели, которого вы используете, нажмите `Добавить` и введите свой ключ;
затем выберите `TEXT EMBEDDING`, в списке выберите поставщика модели, которого вы используете, нажмите `Добавить` и введите свой ключ.
Наконец, обновите страницу и в списке `Установить модель по умолчанию` выберите LLM и Embedding нужные вам модели. Убедитесь, что для вашего ключа активированы соответствующие сервисы, например, я использую модель Embedding от поставщика xxx — нужно зайти на официальный сайт этого поставщика и проверить, требует ли эта модель покупки пакета ресурсов.


# Часть 2. Настройка сервиса ragflow

# Шаг 1. Вход в сервис ragflow
Откройте в браузере `http://127.0.0.1:8008`, нажмите `Sign In` и войдите в сервис ragflow.

Затем нажмите `аватар` в правом верхнем углу и перейдите на страницу настроек. В левой панели навигации нажмите функцию `API`, затем кнопку "API Key". Появится всплывающее окно,

в котором нужно нажать кнопку "Create new Key", чтобы сгенерировать API Key. Скопируйте этот `API Key` — он понадобится позже.

# Шаг 2. Настройка в панели управления
Убедитесь, что версия вашей панели управления — `0.8.7` или выше. Войдите в панель управления под учётной записью суперадминистратора.

Сначала включите функцию базы знаний. В верхней панели навигации нажмите `Словарь параметров` и в выпадающем меню выберите страницу `Настройка системных функций`. На странице отметьте галочкой `База знаний` и нажмите `Сохранить настройки`. После этого в панели навигации появится функция `База знаний`.

В верхней панели навигации нажмите `Настройка моделей`, в левой панели навигации нажмите `База знаний`. В списке найдите `RAG_RAGFlow` и нажмите кнопку `Редактировать`.

В поле `Адрес сервиса` укажите `http://локальный IP вашего сервиса ragflow:8008`, например, если локальный IP моего сервиса ragflow — `192.168.1.100`, я укажу `http://192.168.1.100:8008`.

В поле `API-ключ` вставьте ранее скопированный `API Key`.

В конце нажмите кнопку сохранения.

# Шаг 2. Создание базы знаний
Войдите в панель управления под учётной записью суперадминистратора. В верхней панели навигации нажмите `База знаний`, в левом нижнем углу списка нажмите кнопку `Добавить`. Введите имя и описание базы знаний. Нажмите «Сохранить».

Чтобы повысить способность большой модели понимать базу знаний и качество поиска, рекомендуется при создании базы знаний указывать осмысленное имя и описание. Например, если вы создаёте базу знаний `О компании`, имя базы знаний может быть `О компании`, а описание — `Сведения о компании, например: основная информация о компании, перечень услуг, контактные телефоны, адрес и т.д.`.

После сохранения база знаний появится в списке. Нажмите кнопку `Просмотр` только что созданной базы знаний, чтобы перейти на страницу с подробностями.

На странице подробностей базы знаний нажмите кнопку `Добавить` в левом нижнем углу — так можно загрузить документы в базу знаний.

После загрузки документы будут видны на странице подробностей базы знаний. Теперь можно нажать кнопку `Анализ` документа, чтобы проанализировать его.

После завершения анализа можно просмотреть информацию о полученных фрагментах (чанках). На странице подробностей базы знаний можно нажать кнопку `Тест поиска`, чтобы проверить функцию поиска/ретрива базы знаний.

# Шаг 3. Заставьте Сяочжи использовать базу знаний ragflow
Войдите в панель управления. В верхней панели навигации нажмите `Агенты`, найдите агента, которого нужно настроить, и нажмите кнопку `Настроить роль`.

Слева от распознавания намерений нажмите кнопку `Редактировать функции` — появится всплывающее окно. В окне выберите базу знаний, которую хотите добавить. Сохраните — готово.
