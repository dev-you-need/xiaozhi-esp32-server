# Руководство по использованию плагина взаимных вызовов между устройствами

## Обзор

Функция вызова устройств позволяет двум настроенным устройствам вести двустороннюю связь через голосовой/канал данных. Когда устройство A вызывает устройство B, система работает по следующей схеме:

```
设备A → 授权校验 → MQTT网关 → 设备B远程唤醒 → 建立连接 → 通话建立
```
## Обязательные условия для использования этой функции
1. У вас должно быть как минимум два устройства, и каждое должно быть модели `ESP32-S3`, потому что только `ESP32-S3` поддерживает функцию удалённого пробуждения.
2. На вашем устройстве должно быть `два микрофона`. Но если устройство с `одним микрофоном`, и вы просто хотите попробовать функцию — это тоже возможно, однако будут сильные подёргивания.
3. Вы должны использовать [полное развёртывание модулей](Deployment_all.md) этого проекта, так как вам нужна `панель управления` для управления правами устройств и связью.
4. Вы должны установить и настроить [сервис MQTT-шлюза](mqtt-gateway-integration.md) версии после `27 мая 2026 года`; если сервис MQTT-шлюза уже развёрнут, убедитесь, что версия кода новее `27 мая 2026 года`.

Выше перечислены обязательные условия использования этой функции, далее подробное описание.

## Шаги настройки

### Шаг 1. Включите функцию адресной книги

1. Убедитесь, что версия вашей панели управления — `0.9.4` или выше.
2. Войдите в админ-панель управления
3. Перейдите в **系统功能配置** («Конфигурация системных функций»)
4. Отметьте галочкой **通讯录** («Адресная книга») в списке функций слева
5. Нажмите **保存配置** («Сохранить конфигурацию») для подтверждения

### Шаг 2. Настройте права на вызов между устройствами

1. В верхнем меню панели управления нажмите **通讯录** («Адресная книга»)
2. Слева, в списке устройств под агентом, выберите ваше устройство A (поддерживается поиск по MAC-адресу или имени заметки)
3. В правой панели деталей найдите настройку имени целевого устройства B, например **"小王"**
4. Отметьте галочкой **呼叫权限** («Право вызова») устройства B
5. Нажмите **保存** («Сохранить»)

**Пояснение о двустороннем разрешении:** чтобы устройства A и B могли общаться друг с другом, права на вызов нужно настроить на обеих сторонах. Например:

- В настройках устройства A отметьте устройство B → устройство A может связываться с устройством B
- В настройках устройства B отметьте устройство A → устройство B может связываться с устройством A

### Шаг 3. Добавьте инструмент вызова в настройках агента

1. В верхнем меню панели управления нажмите **智能体管理** («Управление агентами»)
2. В агенте, для которого настраивались контакты устройств, нажмите **编辑角色** («Редактировать роль»)
3. В правой панели деталей нажмите **编辑功能** («Редактировать функции»)
4. Отметьте галочкой инструмент **设备呼叫设备** («Вызов устройства устройством»)
5. Нажмите **保存配置** («Сохранить конфигурацию») для подтверждения
6. Снова нажмите **保存配置** («Сохранить конфигурацию») внешней страницы, после чего перезагрузите устройство

### Шаг 4. Добавьте инструмент удалённого пробуждения в прошивке

1. На базе кода [xiaozhi-esp32](https://github.com/78/xiaozhi-esp32) добавьте инструмент удалённого пробуждения MCP, поддерживаются версии от 2.1.0 до 2.2.6 (версия от 29 мая 2026 года)
2. В файле application.h добавьте объявление функции удалённого пробуждения
    ```cpp
    void RemoteWakeup(const std::string& reason);
    ```
3. В файле application.cc добавьте функцию удалённого пробуждения
    ```cpp
    void Application::RemoteWakeup(const std::string& reason){
        if (!protocol_) {
            return;
        }

        auto state = GetDeviceState();
        
        if (state == kDeviceStateIdle) {
            audio_service_.EncodeWakeWord();

            if (!protocol_->IsAudioChannelOpened()) {
                SetDeviceState(kDeviceStateConnecting);
                if (!protocol_->OpenAudioChannel()) {
                    audio_service_.EnableWakeWordDetection(true);
                    return;
                }
            }
            std::string wake_word = reason;
    #if CONFIG_USE_AFE_WAKE_WORD || CONFIG_USE_CUSTOM_WAKE_WORD
            // Encode and send the wake word data to the server
            while (auto packet = audio_service_.PopWakeWordPacket()) {
                protocol_->SendAudio(std::move(packet));
            }
            // Set the chat state to wake word detected
            protocol_->SendWakeWordDetected(wake_word);
            SetListeningMode(aec_mode_ == kAecOff ? kListeningModeAutoStop : kListeningModeRealtime);
    #else
            // Set flag to play popup sound after state changes to listening
            // (PlaySound here would be cleared by ResetDecoder in EnableVoiceProcessing)
            play_popup_on_listening_ = true;
            SetListeningMode(aec_mode_ == kAecOff ? kListeningModeAutoStop : kListeningModeRealtime);
    #endif
        } else if (state == kDeviceStateSpeaking) {
            AbortSpeaking(kAbortReasonWakeWordDetected);
            SetDeviceState(kDeviceStateIdle);
        } else if (state == kDeviceStateActivating) {
            SetDeviceState(kDeviceStateIdle);
        }
    }
    ```
4. В файле mcp_server.cc добавьте инструмент удалённого пробуждения
    ```cpp
    AddUserOnlyTool("self.remote_wakeup", "Remote wakeup function with configurable parameters",
        PropertyList({
            Property("reason", kPropertyTypeString, "Wakeup reason"),
        }),
        [this](const PropertyList& properties) -> ReturnValue {
            std::string reason = properties["reason"].value<std::string>();
            ESP_LOGI(TAG, "Wakeup reason=%s", reason.c_str());
            auto& app = Application::GetInstance();
            app.RemoteWakeup(reason);
            return true;
    ```
5. Выполните прошивку по [руководству по сборке и записи прошивки](firmware-build.md)
6. Независимо от того, один или два микрофона на устройстве, обязательно включите функцию AEC на этапе сборки!
7. Независимо от того, один или два микрофона на устройстве, обязательно включите функцию AEC на этапе сборки!
8. Независимо от того, один или два микрофона на устройстве, обязательно включите функцию AEC на этапе сборки!

### Шаг 5. Настройте сервис MQTT-шлюза

1. Разверните сервис MQTT-шлюза, см. [документацию по интеграции MQTT-шлюза](mqtt-gateway-integration.md)
2. Если сервис уже развёрнут, убедитесь, что версия кода — от 27 мая 2026 года

## Описание процесса вызова

Подготовьте два устройства, настройте в панели управления права связи и добавьте инструмент вызова в агенте, затем скажите одному из xiaozhi: «呼叫XXX» и наблюдайте, отвечает ли устройство B.

## Частые вопросы

### В: Устройство B не отвечает на вызов?

- Проверьте, онлайн ли устройство B (состояние устройства в панели управления)
- Убедитесь, что в прошивку устройства B корректно добавлен инструмент удалённого пробуждения
- Проверьте, нормально ли работает подключение к MQTT-шлюзу
- Проверьте, полностью ли настроены права в обе стороны

### В: Появляется сообщение «无呼叫权限»?

- В панели управления убедитесь, что для устройства A отмечено право вызова устройства B
- Убедитесь, что настройка сохранена (не просто изменена без сохранения)

### В: Как убедиться, что функция адресной книги включена?

- Если в верхнем меню панели управления отображается пункт «通讯录», значит функция включена

### В: Я говорю вызвать «张山», но он всё время распознаёт как «张三», что делать?
- Сверьтесь с документацией используемого вами сервиса asr и проверьте, поддерживается ли распознавание горячих слов.
- Если вы используете `FunASRServer`, добавьте «张山» в `файл горячих слов` в контейнере, затем перезапустите контейнер.
- Если вы используете сервис `火山引擎`, добавьте `файл горячих слов` в `консоли 火山引擎`, затем вернитесь на `страницу настройки моделей` панели управления и укажите `название файла горячих слов` в настройке `tts 火山引擎`.
