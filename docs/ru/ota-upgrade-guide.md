# Руководство по настройке автоматического OTA-обновления прошивки при развёртывании одного модуля

Это руководство поможет вам настроить автоматическое OTA-обновление прошивки устройств в сценарии **развёртывания одного модуля**, чтобы прошивка устройств обновлялась автоматически.

Если вы уже используете **полное развёртывание модулей**, пропустите это руководство.

## Описание функции

При развёртывании одного модуля xiaozhi-server имеет встроенную функцию управления OTA-прошивками: она автоматически определяет версию устройства и отправляет обновлённую прошивку. Система автоматически подбирает и отправляет последнюю версию прошивки в зависимости от модели устройства и его текущей версии.

## Предварительные условия

- Вы успешно выполнили **развёртывание одного модуля** и запустили xiaozhi-server
- Устройство может нормально подключаться к серверу

## Шаг 1. Подготовьте файл прошивки

### 1. Создайте каталог для хранения прошивок

Файлы прошивок должны находиться в каталоге `data/bin/`. Если этого каталога нет, создайте его вручную:

```bash
mkdir -p data/bin
```

### 2. Правила именования файлов прошивок

Имя файла прошивки должно соответствовать следующему формату:

```
{设备型号}_{版本号}.bin
```

**Пояснение правил именования:**
- `设备型号` — название модели устройства, например `lichuang-dev`, `bread-compact-wifi` и т. д.
- `版本号` — номер версии прошивки; должен начинаться с цифры, допускаются цифры, буквы, точки, подчёркивания и дефисы, например `1.6.6`, `2.0.0` и т. д.
- Расширение файла должно быть `.bin`

**Примеры имён:**
```
bread-compact-wifi_1.6.6.bin
lichuang-dev_2.0.0.bin
```

### 3. Поместите файл прошивки

Скопируйте подготовленный файл прошивки (.bin) в каталог `data/bin/`:

Важное повторяю трижды: файл прошивки для обновления — `xiaozhi.bin`, а не полный файл прошивки `merged-binary.bin`!

```bash
cp xiaozhi.bin data/bin/设备型号_版本号.bin
```

Например:
```bash
cp xiaozhi.bin data/bin/bread-compact-wifi_1.6.6.bin
```

## Шаг 2. Настройте публичный адрес доступа (только для публичного развёртывания)

**Внимание: этот шаг применим только к сценарию развёртывания одного модуля в публичной сети.**

Если ваш xiaozhi-server развёрнут в публичной сети (с публичным IP или доменом), параметр `server.vision_explain` **необходимо** настроить, так как адрес скачивания OTA-прошивки будет использовать домен и порт из этой настройки.

Если у вас развёртывание в локальной сети, этот шаг можно пропустить.

### Зачем нужно настраивать этот параметр?

При развёртывании одного модуля система при формировании адреса скачивания прошивки использует домен и порт из настройки `vision_explain` как базовый адрес. Если параметр не настроен или настроен неверно, устройство не сможет получить доступ к адресу скачивания прошивки.

### Как настроить

Откройте файл `data/.config.yaml`, найдите секцию `server` и задайте параметр `vision_explain`:

```yaml
server:
  vision_explain: http://你的域名或IP:端口号/mcp/vision/explain
```

**Примеры настройки:**

Развёртывание в локальной сети (по умолчанию):
```yaml
server:
  vision_explain: http://192.168.1.100:8003/mcp/vision/explain
```

Развёртывание с публичным доменом:
```yaml
server:
  vision_explain: http://yourdomain.com:8003/mcp/vision/explain
```

### Важные замечания

- Домен или IP должен быть доступен с устройства
- При развёртывании через Docker нельзя использовать внутренние адреса Docker (например, 127.0.0.1 или localhost)
- Если вы используете обратный прокси nginx, указывайте внешний адрес и порт, а не порт, на котором работает этот проект


## Частые вопросы

### 1. Устройство не получает обновление прошивки

**Возможные причины и решения:**

- Проверьте, соответствует ли имя файла прошивки правилу: `{型号}_{版本号}.bin`
- Проверьте, правильно ли размещён файл прошивки в каталоге `data/bin/`
- Проверьте, совпадает ли модель устройства с моделью в имени файла прошивки
- Проверьте, выше ли версия прошивки, чем текущая версия устройства
- Посмотрите логи сервера и убедитесь, что OTA-запросы обрабатываются нормально

### 2. Устройство сообщает, что адрес скачивания недоступен

**Возможные причины и решения:**

- Проверьте, правильно ли указан домен или IP в настройке `server.vision_explain`
- Убедитесь, что порт указан верно (по умолчанию 8003)
- При публичном развёртывании убедитесь, что устройство может получить доступ к этому публичному адресу
- При развёртывании через Docker убедитесь, что не используется внутренний адрес (127.0.0.1)
- Проверьте, открыт ли соответствующий порт в файрволе
- Если вы используете обратный прокси nginx, указывайте внешний адрес и порт, а не порт, на котором работает этот проект

### 3. Как узнать текущую версию устройства

Посмотрите логи OTA-запросов — в них отображается версия, сообщённая устройством:

```
[ota_handler] - 设备 AA:BB:CC:DD:EE:FF 固件已是最新: 1.6.6
```

### 4. Файл прошивки размещён, но не подействовал

У системы есть время кэширования 30 секунд (по умолчанию), можно:
- подождать 30 секунд и снова отправить OTA-запрос с устройства
- перезапустить сервис xiaozhi-server
- уменьшить значение настройки `firmware_cache_ttl`
